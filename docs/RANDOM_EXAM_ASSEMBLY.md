# 随机组卷·难度平衡 功能说明

为每个学生生成**不同但总体难度接近**的试卷；题库不够时在发布前明确告知缺哪类题；组卷结果可导出抽样人工复核，避免某个学生拿到明显更简单的一套。

## 一、管理员可配置的规则

创建随机考试（首页「随机组卷·难度平衡」→「创建随机考试」）时设置：

| 规则 | 说明 |
|---|---|
| 知识点 | 勾选题目分类（可多选）；可填每个知识点具体题数，留空则平均分配 |
| 题型比例 | 各题型百分比，合计须 100%（单选/多选/判断/填空/问答） |
| 难度区间 | 整卷加权难度的 `[最小值, 最大值]`（题目难度 1=简单，2=中等，3=困难） |
| 卷间难度极差 | 公平阈值，任意两份卷难度差不超过该值（默认 0.08，越小越严格） |
| 必考题 | 每位学生试卷中都会出现的题，先占配额 |
| 跨学生不重题 | 勾选后非必考题在所有学生间互不相同（题量要求更高）；不勾选允许跨学生复用，但同一学生卷内不重题 |
| 总题数 / 时长 | 每份卷的题量与考试时长 |

整卷难度按**每题分值加权**计算（高分值难题对卷面难度影响更大）。

## 二、组卷算法（为什么各份卷难度能接近）

代码：`backend/app/Services/ExamAssembly/`

1. **配额规划 `Blueprint`**
   - 必考题先在「知识点 × 题型」格子里占位；
   - 剩余名额用**最大余数法**（Hare-Niemeyer）按知识点均分、再按题型比例分配，保证总题数严格守恒、比例四舍五入误差最小；
   - 逐格比对「需要题数 vs 题库可用题数」，不足即产生 `SHORTAGE` 缺口。

2. **均衡装配 `Assembler`（两层保障）**
   - **分层蛇形发牌**：每个格子内把候选题按难度排序、切成与抽题数相等的若干难度层，层内给各学生发牌，相邻层正反向交替（蛇形）。这样每份卷都取遍「易→难」全谱，难度天然对齐；题库富余时不同学生取不同题，紧张时允许复用但同卷不重。
   - **定向替换修复**：以难度区间中点为目标，反复锁定当前最易卷/最难卷，在同一格子内用「更难/更易且本卷未用过」的题做最优单题替换；对越界施加重罚（先保证全部进入区间），进入后继续收敛极差，直到全部入区间且卷间极差 ≤ 阈值，或无更优替换。

3. **确定性随机 `SeededRandom`**：xorshift32 + 固定种子，相同题库/规则/种子必产生相同试卷，可审计、可复测、可追溯。

## 三、发布前预检（题库不够会被拦下）

点击「重新检查题库」或直接「发布」时，系统试算并返回结构化问题：

| 问题码 | 含义 | 级别 |
|---|---|---|
| `SHORTAGE` | 某「知识点+题型」需要 N 题但题库不足，明确报缺几题 | 阻断 |
| `REQUIRED_INVALID` | 必考题不存在、停用、超范围或题型不在比例中 | 阻断 |
| `UNIQUE_INSUFFICIENT` | 勾选不重题后，非必考题总量不足以支撑全部学生 | 阻断 |
| `DIFFICULTY_UNREACHABLE` | 用题库最难/最易组合都无法落入目标区间（附可行区间） | 阻断 |
| `REQUIRED_DRIFT` | 某必考题难度在目标区间外，可能拉偏整卷 | 警告（不阻断，系统会用其余题抵消） |

页面同时展示**配额矩阵**：每个知识点×题型的「需要 / 已有 / 缺口」。
存在阻断问题时发布按钮禁用；提示「缺哪类题、缺几道」，补题后重新检查即可。

## 四、学生考试

- 发布时一次性为所有启用状态学生预生成个性化试卷，存入 `random_paper_instances` 快照（整场考试稳定不变）；
- 同时创建一张 `type=random` 的试卷容器，复用现有考试记录、计时、评分、排名流程；
- 学生在「在线考试」开考时，接口返回的是**属于他本人**的那份题与分值；交卷只接受其快照内的题目。

## 五、抽样检查与导出（防止有人明显更简单）

随机考试列表 →「抽样检查」：

- 展示平均难度、**卷间难度极差**、标准差、越界试卷数、公平性是否通过；
- 自动抽取**最难卷、最易卷**及若干等距随机卷，用色块逐题并排展示难度分布，可直接人工比对；
- 实际难度的最高/最低值与目标区间对照。

三种导出（链接携带临时 token 鉴权，浏览器可直接下载）：

| 文件 | 用途 |
|---|---|
| `*_sample.csv` | 抽样卷逐题明细（含必考题标记、每题难度/分值、是否越界），Excel 可开 |
| `*_report.md` | 均衡性汇总报告（指标/越界名单/警告/抽样建议） |
| `*_papers.json` | 全部学生试卷完整明细 + 统计 + 种子，供存档与复现 |

另有题目使用次数（`question_usage`）统计，便于发现某道题是否被过度复用。

## 六、数据表

- `random_exam_configs`：组卷规则、配额矩阵、种子、整体难度统计（均值/极差/标准差/越界数/是否通过）；
- `random_paper_instances`：每个学生一场考试一行，含题目 ID 有序列表、题目明细快照、整卷难度、总分、是否越界。

> 迁移：`backend/database/migrations/2026_01_01_000001_create_random_exam_tables.php`
> Docker 初始化：`docker-compose.yml` 的 `db-init` 内联 SQL 已同步建表并补充了 90 道覆盖三知识点/五题型/三档难度的演示题。

## 七、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/random-exams/meta` | 知识点、题型、题库题量与题目简表 |
| POST | `/api/random-exams/preview` | 发布前预检（不落库） |
| POST | `/api/random-exams/publish` | 预检通过后组卷并发布；不足返回 422 + 缺口清单 |
| GET | `/api/random-exams` | 已发布随机考试列表 |
| GET | `/api/random-exams/{id}/audit` | 抽样检查数据 |
| GET | `/api/random-exams/{id}/export/sample` | 抽样 CSV |
| GET | `/api/random-exams/{id}/export/papers` | 全部试卷 JSON |
| GET | `/api/random-exams/{id}/export/report` | 均衡报告 MD |

## 八、自测

无 Laravel 环境也可运行纯引擎自测：

```bash
php backend/scripts/test_assembly.php
```

断言覆盖配额守恒、缺口/可达性预检、必考题、不重题、卷间极差≤阈值、同卷不重题、可复现与导出。
